# 真实支付接入前置条件

当前系统只能进行内部模拟交易。`wechat-platform` 是计划使用的适配器名称，不是已经接入的微信支付产品。将环境变量改为该值不会启用真实付款：服务会拒绝启动，直到补齐经核验的适配器。

## 运营方需要取得的确认

1. 明确经营主体、小程序 AppID、主体与账号关系及实际交易类目。
2. 从微信支付或获准渠道获得平台交易方案，确认个人用户卖家的准入、实名要求及收款身份管理方式。
3. 确认支付后资金的渠道保管方式，以及确认收货或付款满 7 天结算是否被支持；平台数据库中的“余额”本身不构成资金保管能力。
4. 明确结算去向、用户是否需要确认收款、失败及超时规则。不得默认普通商户转账可以实现文档中的结算。
5. 确认全额原路退款、渠道费承担方式、退款失败补偿、结算暂停及投诉处理机制。

请把证书、API 密钥等放在部署环境的秘密管理系统，不提交到仓库。开发团队还需要该获准产品的官方接口文档和测试账号。

## 适配器交付要求

按 `PaymentProvider` 实现创建支付、查询、关闭、退款、结算、操作查询及验签回调。渠道查询结果必须携带真实金额、流水号和付款时间。退款与结算使用系统提供的稳定操作 ID；渠道“已受理”应返回 PENDING，只有明确成功才能返回 SUCCEEDED。

支付通知必须完成渠道签名、证书和时间校验，解密后核对主体、AppID、币种、交易订单与金额。还需实现退款和结算状态查询／通知，以及卖家准入资料与收款身份映射。当前模拟签名协议仅用于测试，不可以替换微信真实验签。

支付方案核验记录、接入代码审核和真实小额付款／退款／结算测试均通过后，才允许设置 `PAYMENT_CAPABILITIES_VERIFIED=true`。自动启动门槛只负责阻止错误配置，不替代运营审核。

## 必须完成的真实验证

正常付款后交付与提前结算；7 天自动结算；72 小时未交付退款；付款取消后的迟到支付；重复回调；退款／结算超时与恢复；渠道暂时不可用；收款人确认流程；账单金额核对；真实账号取消订阅通知。

如果个人卖家或延迟结算能力未被获准，保持生产关闭，继续内部测试，并重新确认业务范围。不得把内部模拟渠道或线下付款作为这次要求的真实资金试运营交付。
